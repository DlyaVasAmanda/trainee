# Тренировки

Личный дневник тренировок в виде PWA: план на неделю, запись подходов в зале, история и прогресс.
Работает офлайн, ставится на экран телефона, данные хранятся только на устройстве (IndexedDB).

## Возможности

- **Сегодня**: полоса недели и тренировка выбранного дня, старт по плану в одно касание.
- **Тренировка**: подходы для силовых (кг × повторы), упражнений со своим весом и кардио (км, минуты, темп). Подставляется прошлый результат, показывается цель из шаблона.
- **План**: шаблон или отдых на каждый день недели, редактор шаблонов (подходы × повторы, порядок упражнений).
- **История**: тренировки, объём, серия недель подряд.
- **Прогресс**: подходы по группам мышц за 7 дней, график по упражнению (оценка 1ПМ по Эпли, повторы или километры).
- **Упражнения**: библиотека базового сплита по группам мышц и свои упражнения, экспорт и импорт JSON и CSV.

Цвет группы мышц повторяет цвета соревновательных блинов: грудь красная, спина синяя, ноги жёлтые, плечи зелёные.
«Блин» дня в плане разделён на цвета групп этого дня.

По умолчанию стоит классический сплит на 3 дня: Пн «Грудь + трицепс», Ср «Спина + бицепс», Пт «Ноги + плечи».

## Аккаунты и синхронизация

Вход по email и паролю (Supabase Auth). Приложение **local-first**:

- все записи сначала сохраняются в IndexedDB на устройстве, поэтому в зале без сети всё работает;
- изменения копятся в очереди `outbox` и уходят в облако, когда появляется сеть: сразу после правки, при возврате в приложение и раз в минуту;
- при конфликте одной записи побеждает более поздняя правка (last-write-wins по времени изменения на устройстве, проверка в триггере БД);
- у каждого пользователя своя локальная база (`trainee-<uid>`), а режим без аккаунта использует отдельную (`workout-tracker`);
- после входа тренировки, записанные без аккаунта, можно перенести в аккаунт;
- стартовые упражнения и шаблоны имеют одинаковые id на всех устройствах, поэтому дубликатов не появляется.

Если `config.js` пуст, приложение работает как раньше: без аккаунтов, только на устройстве.

### Настройка Supabase (один раз)

1. Создай бесплатный проект на [supabase.com](https://supabase.com).
2. В **SQL Editor** выполни `supabase/schema.sql`. Он создаст таблицу `records`, RLS-политики и триггер LWW.
3. В **Authentication → URL Configuration** укажи Site URL `https://dlyavasamanda.github.io/trainee/` и добавь его в Redirect URLs. Туда ведут ссылки подтверждения email и сброса пароля.
4. Скопируй из **Project Settings → API** значения `Project URL` и `anon public` key и впиши их в `config.js`.
   anon key публичный, его безопасно хранить в репозитории: доступ к данным ограничен RLS, и каждый видит только свои записи.

По умолчанию Supabase требует подтвердить email после регистрации, это настраивается в **Authentication → Providers → Email**.
Встроенная отправка писем Supabase ограничена несколькими письмами в час. Для личного использования этого хватает, для большего нужен свой SMTP.

## Запуск

```bash
python3 -m http.server 8080
# открыть http://localhost:8080
```

Service worker и установка на экран работают только по `http(s)`, двойной клик по `index.html` не подойдёт.

### GitHub Pages

Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
Затем открой `https://dlyavasamanda.github.io/trainee/` на телефоне и выбери «На экран «Домой»».

## Обновления

Оболочка кэшируется по схеме stale-while-revalidate: после деплоя новая версия подтягивается в фоне
и появляется при следующем открытии приложения. При изменении списка файлов увеличь `CACHE` в `sw.js`.

## Данные

База IndexedDB версии 3 содержит хранилища `exercises`, `workouts`, `templates`, `meta` (план недели, версия сида, курсор синхронизации) и `outbox` (неотправленные изменения).
Старые базы версий 1 и 2 мигрируют автоматически.
В облаке каждая запись хранится как строка `records(user_id, kind, id, data jsonb, deleted, updated_at, server_ts)`.
Без аккаунта регулярно делай «Экспорт JSON», потому что очистка данных сайта удаляет всю историю.
